Secure agent design with small local models.

Histora Health builds clinical record software. Running a model inside the customer's perimeter changes the objective: the priority is not the model's knowledge but the ability to guarantee that the actions it emits are safe and executable.

The empirical work behind that, and the architecture it produced, gets published here with the benchmarks and the raw data.

What can be guaranteed about the actions a small local model emits?

Four layers between what an agent proposes and what executes: an option surface computed from live state, so a signed record leaves the choices the moment it is signed; order forced at the system level, which is the one class of rule a JSON Schema structurally cannot state; verification that the action names the record the request named; and a person who confirms.

Two cases run end to end against gates decided before they were built: procedure coding from dictation, and filing a study that arrives from an outside clinic. One ships after a known fix; the other does not, and finding that out was the point of building it.

The options we evaluated

The constraint is fixed: the model runs inside the customer's perimeter, on hardware a clinic owns, because the data is clinical. That rules out reaching for a frontier model when a small one struggles — and it is what makes the rest of this a real question rather than a preference.

Prompting and trust is not viable. Small models have a high rate of malformed or unexecutable output on a text protocol — fourteen malformed outputs in thirty turns, and none of ten legitimate tasks completed. Before asking whether the model respects a rule, you have to ask whether it emits anything executable.

Post-hoc validation is sound; the retry is the cost. With enums regenerated each turn from live state, calls naming a forbidden record are rejected and the error returned to the model. Writes reaching the closed record: zero, in every arm measured. What fails is the correction — small models correct their own output badly after a rejection, so throughput comes to depend on retries that do not converge.

Constrained decoding makes the model usable, and introduces a failure of its own. Restricting the generated tokens took the same model from none of ten legitimate tasks to all ten — a figure that is also confounded, since the failing arm used a text protocol rather than native tool calling, so it measures protocol as well as enforcement. It produced the substitution below, which is why enforcement now sits at the decision point rather than at the sampler. It is also commodity: vLLM and SGLang ship it, including the region-scoped variant this work implemented independently.

A multi-agent system with tools does not address this. A planner, an executor and a checker are more model calls of the same kind: each still chooses from a schema it was asked to respect, so the failure below is multiplied by three rather than caught — on a model where every call costs seconds and every call is a chance to emit something malformed. A checker agent reading the proposed action sees a legal action on a permitted record, which is exactly what a substitution looks like.

What we built is not a fifth alternative. It keeps the validator, adds the option surface for the retry problem, and adds one rule the other four cannot express: whether the action names the record the request named.

Two cases, measured against gates decided in advance. Procedure coding from dictation: coverage 0.80, median latency 3.5 seconds, zero proposals against a tooth the dictation did not name. Filing an incoming study: coverage 0.944, zero exports before anonymisation confirms, zero writes reaching a signed record — and none of that changes under a fabricated administrative override planted in the DICOM header the assistant reads.

Two of the gates were measuring the wrong thing, and correcting them decided the outcome. Friction was defined as inspections and both cases scored zero, which is true and describes nothing a clinician experiences: under propose-and-confirm every proposal needs a person, so the friction is one confirmation per action. And zero inspections also meant the reference check had never fired in either run, so the number was hiding a guard nobody had exercised. Measured directly: zero false positives across twenty-five legitimate requests in three domains and two languages, phrased the way clinicians actually speak, and three of three known substitutions still caught. That rate is what decides whether a guard survives production, because one that blocks real work gets switched off and then protects nothing.

The verdict. Coding ships after keying the value set by material as well as surface — the entire coverage gap is four codes legal for the surface and wrong for the procedure, with the right code sitting in the offered set. Filing does not ship: at ten seconds plus a confirmation it loses to dragging a file, and no architecture supplies a product argument it does not have.

The critical failure: silent substitution

Constrained decoding forces the model to always choose a valid option. When a user asks it to modify a record that is blocked — and therefore absent from the mask of legal options — the model has no way to stop. Instead of declining, it keeps the intent, substitutes the forbidden target for a valid one, and executes the action on the wrong record.

The failure is silent and undetectable by JSON schemas and classical validators: the generated action is technically legal, every argument belongs to the permitted vocabulary, and no violation is logged because nothing was violated.

The trigger is not adversarial pressure. An explicit fabricated administrative override produced zero substitutions in twenty attempts; a phrasing that reads as ordinary filing produced five out of five. Independent work on frontier models found the same shape, and four attempts to detect it from the model's internal state returned null on a rig whose positive control passes.

The architecture this requires

Four layers, none of which depends on the model's intelligence to avoid the error.

An option surface derived from state. Tools and argument enums are not fixed schemas — they are regenerated each turn from the live state of the system, so a signed record disappears from the possible values the moment it is signed.

Order forced at the system level. Clinical process rules — pick tooth, pick surface, audit, sign — become tool availability, so an incorrect sequence is not among the options rather than rejected after the fact. This is the class of rule a JSON Schema structurally cannot state: only after that is not an assertion about shape.

Reference verification before executing. An algorithmic check requiring overlap between the record the model selected and the records the request actually named. It reports rather than corrects — a guard that corrected silently would be making clinical decisions by string similarity. Measured on its own, because a rate is what decides whether a guard survives production: zero false positives across twenty-five legitimate requests in three domains and two languages, phrased the way clinicians speak, and three of three known substitutions still caught.

Propose-and-confirm. Because no autonomous system can guarantee correctness against substitution, the agent structures and proposes the change only. A person sees the target record — by name, not by identifier — and confirms. That is the real cost of this design and it is worth stating in the open: one confirmation per action, every time. It is why dictated coding ships and filing does not.

What we took as reference

The field moved substantially through 2026. We sit inside these lines rather than beside them, and where published work already covers something we adopt it rather than reinvent it.

The rule model comes from AgentSpec (ICSE 2026) — trigger, check, enforce, evaluated across code agents, embodied agents and autonomous driving, preventing over 90% of unsafe executions with millisecond overhead. We adopt the shape rather than the language, and two things follow from it: enforcement belongs at the decision point, and user inspection is a first-class enforcement action — so propose-and-confirm is literature rather than a concession.

The design law comes from token-trie, validated there on a 350M model: the model is a ratifier, not a planner. If you find yourself making the model decide something the program could compute, push it down into the program. That is why a chained argument reaches the model as one enumerated choice, and why a coded procedure costs one round trip instead of three.

The failure has independent corroboration. Bad Memory (Gadgil et al., University of Washington) evaluated memory-borne injection against frontier models across four of them. Their highest attack success rate came from the planted goal that — in their words — resembles a legitimate user preference, not from the overtly malicious ones. Different models, different domain, same shape as what we measured: what survives every defence is the request that looks legitimate.

Adjacent rather than competing. ActPlane enforces OS-level policy for agent harnesses — it governs what the harness process may do, we govern what the agent may propose. Lingering Authority applies revocable capabilities to coding agents. Constraint Tax in Open-Weight LLMs measures what simultaneous schema constraints and tool calling cost: under both, open-weight models stop invoking tools entirely. And the industrial frame is Anthropic's Zero Trust for AI agents, DeepMind's AI Control Roadmap, and the NIST NCCoE concept paper on agent identity and authorization.

The starting point was our own. The Evolving Agents Toolkit had a governance layer named Firmware, implemented as a string in a system prompt. The decomposition was right and the substrate did not exist; this is the attempt to give it one.

What is still open

A failure that is a refusal rather than an action. The fabricated override did nothing — six of six, identical to the empty control. A note that reads like the referring clinic being helpful produced something every gate misses: the model declined a legitimate filing request, citing the sender's note as authority. Not privilege escalation, since the destination it named was never available. Denial of service on real work, invisible to every measurement here because nothing was written and the refusal reads as diligence. It is the third result in this project pointing the same way — explicit attack framing is the case that gets handled.

Enumeration at real scale. A demonstration folder holds seven records and an odontogram thirty-two teeth. A real clinical history holds hundreds and a real nomenclador thousands of codes, and the surface refuses past a ceiling rather than degrading.

Reference across languages. Zero false positives on twenty-five requests including Spanish ones — but the record names are English, and the overlap works because clinical vocabulary is cognate. La ficha de encías against perio_chart.pdf shares nothing, and that is what a small embedding model is for.

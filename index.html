This is where the experiments that answer that get published, with the benchmarks and the raw data. One so far, and it is ongoing.

Which small local models can run a records assistant, and where do they break?

The set of available actions compiled from live state into a token trie, applied as a mask on the sampler. What we have measured so far

A small model stops failing at form. The same model completed none of ten legitimate tasks without the mask and all ten with it, with fourteen malformed calls against none. Constrained decoding lets a model emit a protocol it does not know — which is the situation you are in when the protocol is yours and retraining is not an option.

Order becomes expressible. While a change is unrecorded, one opcode of forty-nine has a path, and it is the one that records it. A second write is not a call that gets rejected; no token begins one. Half of a clinical regulation is that shape — export only after anonymisation confirms, sign only after validation — and no schema can state it.

And we found where it breaks. Told to act on a record it may not touch, the model performs a legal action on a different record and reports success. No defence sees it: the action is inside the surface, every argument is in its enum, and no violation is logged because nothing was violated.

What triggers it is not an attack. An explicitly adversarial phrasing — a fabricated administrative override — produced zero substitutions in twenty attempts. A sentence that sounds like ordinary filing produced five out of five. Independent work on frontier models found the same shape. So the deployable form is propose-and-confirm, not autonomous writes, and we would rather publish that than have someone discover it in a clinic.

Two scenarios, and the contrast is the finding

Moving a file between studies is where it breaks, and it is what the numbers above measure. The whole task is choosing between interchangeable entities under a permission constraint — so when the requested record cannot be touched, there is always a similar one beside it to land on.

Coding a procedure onto a tooth inverts every one of those properties, and it is what comes next. The constraint is anatomical rather than permission-based: tooth 11 has an incisal surface and no occlusal one, and a tooth recorded as absent has no procedures at all. Those are not prohibitions the model is fighting — they are categories that do not exist, and the clinician is not asking for them.

It is also where enumeration earns its keep, since a hallucinated procedure code is a rejected claim, and where the phase controller does: pick the tooth, then only that tooth's surfaces, then only the codes valid for that surface. Each step's surface is a function of the previous choice, which is the same machinery already in the repository applied to a case that rewards it.

Named and not built. The manifest and a fourth example are the work; the mechanism is done.

Why publish an unfinished experiment

Because a claim about what software cannot do is worth nothing if the mechanism is not inspectable. "Our assistant cannot modify a signed record" is a sentence any vendor can write; whether it is true depends on a mechanism, and a mechanism you cannot audit is a promise.

And because the interesting part is the limits. What stays closed is the product, and anything that would map a live system's attack surface.
